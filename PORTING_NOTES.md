# Porting notes: Minecraft 1.21.11

This branch is a port of Veil (from the 1.21.1 baseline) to target Minecraft
**1.21.11**. The build config was originally written without being able to
compile anything, because this dev sandbox's network policy blocks every
host the build needs (`maven.fabricmc.net`, `maven.neoforged.net`,
`libraries.minecraft.net`, `piston-meta.mojang.com`, `repo.spongepowered.org`,
`maven.parchmentmc.org`, `maven.blamejared.com`, `maven.su5ed.dev`) - only
Maven Central was reachable there. A real `./gradlew build` run on GitHub
Actions (which *can* reach those hosts) has since confirmed one real
architecture issue and fixed it - see "Confirmed via CI" below.

## Confirmed via CI

A real CI build failed at configuration time in the `neoforge` subproject:
`Tried to add a dependency to configuration ':neoforge:additionalRuntimeClasspath',
but there is no additional classpath anymore for Minecraft 1.21.11. Add the
dependency to a standard configuration such as implementation or
runtimeOnly.` ModDevGradle's `additionalRuntimeClasspath` helper no longer
exists starting with Minecraft 1.21.11. Fixed in `neoforge/build.gradle` by
dropping that wrapper from the `jarJar(api(...))` calls and depending
directly.

A second CI run got past that and much further, surfacing two more real
issues plus the actual blocker this port can't config its way past. A third
run confirmed the fixes below actually work end-to-end: both
`:common:createMinecraftArtifacts` and `:neoforge:createMinecraftArtifacts`
now succeed, really downloading, merging, and renaming real Minecraft
1.21.11 client/server jars via NeoForm. The *only* remaining failure in that
run was `fabric:validateAccessWidener`.

- **`net.neoforged:neoform:1.21.11-UNKNOWN-VERIFY` not found** - the
  placeholder this port originally left. Fixed by cloning
  `neoforged/NeoForge`'s own `1.21.11` branch directly and reading its
  `gradle.properties` (`neoform_version=20251209.172050`), giving the real
  value `1.21.11-20251209.172050`.
- **Parchment does have a 1.21.11 release after all** - this port had
  disabled it, guessing it wasn't published yet. The official
  `NeoForgeMDKs/MDK-1.21.11-ModDevGradle` template (auto-generated by
  NeoForge's own mod generator, last updated Oct 2026) pins
  `parchment_mappings_version=2025.12.20` for `1.21.11`. Re-enabled in all
  three subprojects with that value. The same template also gave more
  current/authoritative values than this port's earlier web-search guesses:
  `neoforge_version` is now `21.11.45` (was `21.11.38-beta`) and
  `minecraft_version_range` is now `[1.21.11]` (the official template's own
  format, a closed single-version range, not `[1.21.11,1.21.12)`).
- **The real blocker: Minecraft's renderer API changed substantially between
  1.21.1 and 1.21.11, and `fabric:validateAccessWidener` caught it.** CI
  output showed dozens of `Could not find method/field/class (...)` errors
  against `veil.accesswidener`, naming real Minecraft rendering classes:
  `com.mojang.blaze3d.shaders.Uniform` (most of its `set*`/`setMat*`
  overloads), `GlStateManager.BlendState`/`TextureState`,
  `RenderType.CompositeRenderType`/`CompositeState`, a long list of
  `RenderStateShard` inner classes, `ShaderInstance`/`EffectInstance`'s
  `lastProgramId` field, `GameRenderer.getFov`, `BufferUploader`'s
  `lastImmediateBuffer` field, `RegistryDataLoader.createContext`, and more.
  **This is not a config problem - it's the real rendering-internals rework
  this port flagged from the start as out of scope**, and it means Veil's
  mixins (which hook most of these same classes) will need real source
  changes, not just build-file tweaks. Fixing it properly needs the actual
  1.21.11 mappings/source to find the renamed/replaced equivalents for each
  broken member, which is a different kind of work than everything else in
  this file - see "To finish this port".

## What changed (build config only)

- `gradle.properties`: `minecraft_version`, `minecraft_version_range`,
  `fabric_version`, `fabric_loader_version`, `neoforge_version`,
  `neoforge_version_range`, `neo_form_version`, `parchment_version`,
  `sodium_version` updated to best-available/confirmed values (see above and
  inline comments for sourcing - most are now confirmed against official
  NeoForge/NeoForgeMDKs sources rather than web-search guesses).
- `common/build.gradle`, `fabric/build.gradle`, `neoforge/build.gradle`: the
  Parchment mappings overlay is enabled, confirmed available for 1.21.11.
- `fabric/build.gradle`, `neoforge/build.gradle`: optional compile-time compat
  dependencies (Iris, ReplayMod, Flashback, CameraTweaks, Forgified Fabric
  API) have inline `PORT TODO` comments; Iris was bumped to the best version
  found (1.10.6), the others could not be confirmed for 1.21.11 and are left
  as-is (stale, will almost certainly fail to resolve).

## What was *not* attempted

No source-level API migration was attempted - see the `validateAccessWidener`
finding above. Veil hooks deeply into Minecraft's renderer internals via
mixins across `common`, `fabric`, and `neoforge`, and those internals changed
substantially between 1.21.1 and 1.21.11. Fixing this needs someone (or an
agent) with access to the actual 1.21.11 mappings/decompiled source to work
out the correct replacement for each broken access-widener entry and mixin
target - guessing replacement signatures without that would be worse than
leaving the real compiler/validator error in place.
